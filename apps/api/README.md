# api

The NestJS API (`deploy-api-skeleton`), with its PostgreSQL connection and migration history (`add-persistence-skeleton`).

- **Database.** The API connects to the database `DATABASE_URL` names and refuses to start without it. The connection is opened on the first query, so `/health` answers whether or not the database is reachable. The pool and the Drizzle database are provided by `src/database/database.module.ts`.
- **Migrations.** One drizzle-kit history (ADR-0011): `drizzle.config.ts` reads every context's schema through `src/database/schema.ts` and writes to `migrations/`, which ships in the image beside `dist/`. Generate a migration after changing a schema with `pnpm nx run api:db-generate` (no database needed), and review the SQL it writes. Apply the history with `pnpm nx build api` then `DATABASE_URL=postgres://… node apps/api/dist/migrate.js`; deliveries run the same command as the Compose service `migrate` before the API starts. It exits `1` on any failure, printing the error with the URL and its password redacted.
- **Configuration.** `src/config/` validates `DATABASE_URL` (required), `PORT` (default `3000`, `1`–`65535`) and `APP_VERSION` (default `unknown`) with Zod when the API is created, and provides them under `APP_CONFIG`. An invalid environment stops the API before it listens, naming each invalid variable and never its value. Nothing else in `src/` reads `process.env` (lint), except `migrate.ts`.
- **Logs.** One JSON object per line, through Nest's `ConsoleLogger` (`src/logging/`). Properties named as secrets (`SECRET_KEYS`: `password`, `token`, `apiKey`, `databaseUrl` and the rest, in any letter case and at any depth) are written as `[REDACTED]`. Redaction does not reach message strings, error messages or stacks, so **a secret goes only into a log entry's structured params, never into its message**: `logger.log('Connected.', { databaseUrl })`, never ``logger.log(`Connected to ${url}.`)``.
- **Errors.** Every error response is an RFC 9457 problem document (`application/problem+json`: `type` `about:blank`, `title`, `status`, and `detail`, `code` or `errors` where they apply), rendered by `src/http/problem.filter.ts`. A controller answers a handler's `Result` with `toResponse(result)` from `@basis/shared-infrastructure`: a `DomainError`'s kind sets the status (`not-found` 404, `conflict` 409, `rule-violated` 422, `forbidden` 403). A route parameter whose decorator names a schema (`@Body({ schema })`, from a context's `contracts`) is validated, and refused with `400` and its issues. A defect, or an HTTP exception of `500` or above, is answered without its message and logged.
- **Tests.** Unit specs beside their files (`pnpm nx test api`); integration specs in `tests/integration/` against a throwaway PostgreSQL per run (`pnpm nx run api:integration`, needs Docker); end-to-end in `apps/api-e2e`.
